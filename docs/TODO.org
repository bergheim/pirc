Spike: one command clones the *current* Pi conversation into a new git worktree and a new Herdr workspace, without mutating the source pane.

This is host-only, clean-tree-only, and must not run against the live =~/.pi= config checkout.

** UX

Command (name bikesheddable):

: /herdr-fork [focus instructions]

Examples:

- =/herdr-fork= — clone full context into a new worktree, no compact.
- =/herdr-fork focus on the herdr worktree create JSON shape= — clone, then compact *the clone only* with that prompt.

What the operator sees:

- This pane, this session file, this cwd, this branch: untouched. No compact, no =/clone=, no =/fork=, no cwd change, no pane close.
- A new Herdr workspace appears in the sidebar, *grouped under the parent repo workspace* (Herdr worktree grouping).
- That workspace has a Pi agent that already has the conversation (or a compact of it).
- The new checkout is a real git worktree on a new branch based at the source =HEAD=.

Do *not* overload Pi's built-in =/fork= (rewind to a previous user message) or =/clone= (replace *this* TUI with a duplicate session at the same cwd). Those stay as they are.

** Why this order (and not compact-then-create)

1. =/clone= / =/fork= switch *this* TUI to the new session. Compact then mutates *this* context. Wrong pane.
2. =herdr worktree create= does not inherit a Pi session. It creates a git checkout + a Herdr workspace + a *shell* pane. That *is* Herdr "picking it up" — there is no later discovery step.
3. =pi --fork <source>= must run in the *new* cwd so the cloned session is stored in that project's session namespace, not =~/.pi='s.
4. =/compact [prompt]= is lossy for the model (full JSONL history remains; =/tree= can revisit). Run it only on the clone, and only if the operator passed focus text.

Pi's =examples/extensions/handoff.ts= is a possible later alternative to compact ("extract what matters"). Out of scope for this spike.

** Preconditions (reject otherwise)

- =HERDR_ENV=1=, =HERDR_SOCKET_PATH= set, =HERDR_PANE_ID= set. The command is a no-op with a clear error outside Herdr.
- =herdr= CLI on PATH and the socket is reachable (=herdr workspace list= or equivalent).
- Current Pi session is persisted (has a session file / id). If the session has not been saved yet, refuse — same class of failure as Pi's own "session must be saved first" fork guard.
- Git repo, host-visible, not the live Pi config:
  - Resolve repo root from the *project* cwd Pi is running in, not from Herdr's focused workspace if they diverge.
  - Refuse if repo root is =~/.pi= or otherwise the live bind-mount config checkout.
  - Refuse if not a git work tree, or if =git status --porcelain= is non-empty. Dirty files do *not* copy into a new worktree; the spike does not invent a stash/commit path.
- New branch name is unique (see Open questions for collision behavior).
- Host-only. No devcontainer, no =just wt=, no in-container tmux. Worktrees land where Herdr puts them (= [worktrees] directory=, default =~/.herdr/worktrees=), which is typically *outside* a container mount.

** Non-goals

- Copying uncommitted changes into the new worktree.
- Devcontainer / jolo =just wt= / worktrunk / =@yassimba/pi-herdr-worktree=.
- Mid-history rewind (Pi =/fork= from an old user message).
- Reusing an existing worktree or branch as "the" destination.
- Auto-closing the source pane, auto-deleting a failed checkout, merge-back, or cleanup UX.
- Changing =agent/extensions/herdr-agent-state.ts= (Herdr-managed; reinstall overwrites it).

** Exact flow

1. *Validate.* Env, herdr socket, persisted session, git root, not =~/.pi=, clean tree. Fail before any create.
2. *Name.* Derive a branch slug from focus text if present, else a timestamp/short-hash. Sanitize to a legal git branch (e.g. =feat/herdr-fork-<slug>=). Capture: repo root, =HEAD=, source session path *and* id, current Herdr workspace/pane ids.
3. *Create checkout + workspace.*
   : herdr worktree create --cwd <repo-root> --branch <branch> --base HEAD --label <short> --no-focus
   Never =--focus=: this agent would follow the UI into the new workspace mid-command.
4. *Parse JSON. Do not predict ids.* Capture at least: new workspace id, checkout path, root pane id. If the shape is not what we assumed, stop and print the raw JSON (see Open questions).
5. *Start Pi in that pane, forking the source session into the new project.*
   : herdr agent start <unique-name> --kind pi --pane <root-pane-id> -- --fork <source-session-path>
   Use argv arrays, no shell interpolation of paths. Unique agent name so a second spike does not collide. The pane must be at an interactive shell prompt; =herdr agent start= already waits for agent readiness (default 30s).
6. *Wait until the new agent is idle* (=herdr agent wait … --until idle=). If it sits in =blocked=, report and stop — do not send compact onto a permission prompt.
7. *Optional compact, clone only.* If the operator passed focus text:
   - Try =herdr agent prompt <name> "/compact <focus text>"= (or equivalent send).
   - *Spike fallback:* if slash commands are not executed via =agent prompt= (they may be typed as a user message instead of a command), stop and tell the operator to run =/compact …= by hand in the new pane. Do not invent a Pi RPC compact call unless we already have evidence it is the reliable path.
   - Never compact the source session.
8. *Report. Leave the source pane running.* Print: branch, checkout path, workspace id, pane id, new agent name, new session id/path if discoverable, and whether compact ran or was left as a manual step.

** Semantics to keep straight

- Herdr does *not* discover git worktrees created with =git worktree add=. Only =herdr worktree create= / =open= make a grouped workspace.
- =worktree create= = workspace + shell. It does not start Pi and does not copy a session.
- =pi --fork <path|id>= copies the source session into a *new* session file in the *current* project's session dir. That is why it must run with cwd = the new worktree (which =herdr agent start= should inherit from the pane/workspace cwd).
- Compaction is lossy for the model; the clone's JSONL still has history.
- Source pane: no =ctx.fork()=, no =ctx.newSession()=, no compact, no close.

** Failure safety

- Source pane is sacred. No close, no compact, no session switch, no cwd change, on any path including errors after step 3.
- If create succeeds and agent start fails: *keep* the worktree/workspace. Print the exact recovery command (=herdr agent start … -- --fork …=) and the exact remove command (=herdr worktree remove --workspace <id>=). Do not auto-remove.
- If start succeeds and compact fails/is unsupported via prompt: keep the clone running with full context; report that compact is manual.
- Quote-safe argv; do not interpolate focus text into a shell string.
- Do not =git reset=, =stash=, or dirty the source tree to make the clean-tree check pass.

** Test matrix (disposable *host* git repo, not =~/.pi=)

Happy path:

- Clean repo, Herdr pane, persisted session that contains a unique marker string in the conversation.
- =/herdr-fork= with no focus: new grouped workspace, Pi idle, marker still in context, cwd is the worktree, branch is the new one, source session file and source pane unchanged (same id, no new compaction entry).
- =/herdr-fork focus on MARKER=: compact (or documented manual fallback) only on the clone; source JSONL has no new compaction entry; clone still knows MARKER.

Isolation:

- Edits in the worktree do not appear in the source tree; source dirty check still clean after clone-side edits (until we touch shared git objects/branches — the source *branch* should be unchanged).

Failures (no checkout, or leftover checkout retained with recovery text — never source mutation):

- Dirty source tree.
- Not a git repo.
- Not in Herdr (=HERDR_ENV= unset).
- Target is =~/.pi=.
- Branch name collision.
- =herdr= socket down.

** Success criteria

- One command from a Herdr-hosted Pi session produces a visible grouped worktree workspace with a usable inherited conversation.
- Source pane/session/cwd/tree are bit-wise unchanged aside from this TODO's own git work (the spike implementation lives in =~/.pi=, the *target repo* of the fork is a different tree).
- Failures are non-destructive to the source and do not silently delete a successful checkout.
- Spike log records: exact commands, raw create JSON, ids, whether =--fork= landed in the worktree session dir, and whether =agent prompt /compact= actually compacted.

** Likely implementation

New *local* Pi extension beside =agent/extensions/herdr-agent-state.ts= (e.g. =agent/extensions/herdr-fork.ts=). Register =/herdr-fork=. Call =herdr= via =child_process= with argv arrays. Read session path from =ctx.sessionManager= the same way the managed Herdr integration already does.

Do *not* edit =herdr-agent-state.ts=. Do *not* install =npm:@yassimba/pi-herdr-worktree= (worktrunk + split-pane, no new workspace row).
