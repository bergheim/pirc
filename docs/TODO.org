Spike: one command clones the *current* Pi conversation into a new git worktree and a new Herdr workspace, without mutating the source pane.

This is host-only, clean-tree-only, and must not run against the live =~/.pi= config checkout.

Claude and Codex reviews are in the LOGBOOK. Decisions below already include them.

** UX

Command (name bikesheddable):

: /herdr-fork [focus instructions]

The optional argument is *both* the compact prompt *and* the branch-slug source. No extra flags this spike. Say that in command help.

Examples:

- =/herdr-fork= — clone full context into a new worktree, no compact.
- =/herdr-fork focus on the herdr worktree create JSON shape= — clone, then (once compact-via-prompt is proven) compact *the clone only* with that prompt.

What the operator sees:

- This pane stays on this session, cwd, and branch. No compact, no =/clone=, no =/fork=, no cwd change, no pane close. The invocation itself *will* append to this session JSONL — that is expected.
- A new Herdr workspace appears in the sidebar, *grouped under the parent repo workspace*.
- That workspace has a Pi agent that already has the conversation (or a compact of it, after the compact gate).
- The new checkout is a real git worktree on a new branch based at the captured source commit.

Do *not* overload Pi's built-in =/fork= (rewind to a previous user message) or =/clone= (replace *this* TUI with a duplicate session at the same cwd).

** Why this order (and not compact-then-create)

1. =/clone= / =/fork= switch *this* TUI to the new session. Compact then mutates *this* context. Wrong pane.
2. =herdr worktree create= does not inherit a Pi session. It creates a git checkout + a Herdr workspace + a *shell* pane. That *is* Herdr "picking it up".
3. =pi --fork <source>= must run in the *new* cwd so the cloned session is stored in that project's session namespace.
4. =/compact [prompt]= is lossy for the model (JSONL history remains; =/tree= can revisit). Run it only on the clone, only if focus text was passed, and only after the compact gate below.

Pi's =examples/extensions/handoff.ts= is a later alternative to compact. Out of scope.

** Preconditions (reject otherwise)

- =HERDR_ENV=1=, =HERDR_SOCKET_PATH= set, =HERDR_PANE_ID= set. Clear error outside Herdr.
- =herdr= CLI on PATH; socket reachable.
- *This* Pi is idle before we capture anything. Extension commands can run while streaming; an in-flight turn will not be in the file.
- =ctx.sessionManager.getSessionFile()= returns a readable regular file. =isPersisted()= only means persistence is *enabled* — not that a file exists. Once idle, Pi writes synchronously; that is the flush. No extra fsync ritual.
- Current leaf id equals the last persisted leaf. =pi --fork= (0.84.3 =forkFrom=) copies the whole JSONL and restores the last persisted leaf, *not* =getLeafId()=. After =/tree= away from tip, refuse: "=/tree= away from tip is unsupported" until that semantic is solved.
- Git repo, host-visible, not the live Pi config:
  - Resolve repo root from the *project* cwd Pi is running in, not from Herdr's focused workspace if they diverge.
  - Refuse live config by =realpath= of the git *common dir* against =~/.pi=, not a string match (bind-mount aliases).
  - Refuse if not a git work tree, or if =git status --porcelain= is non-empty. Error must *list* the blocking paths. Untracked files are not copied; still refuse any porcelain this spike (tracked-only is a later relaxation). Dirty files do not appear in the new worktree; no stash/commit path.
- Host-only. No devcontainer, no =just wt=, no in-container tmux. Worktrees land where Herdr puts them (=[worktrees] directory=, default =~/.herdr/worktrees=), typically outside a container mount.

** Non-goals

- Copying uncommitted changes into the new worktree.
- Devcontainer / jolo =just wt= / worktrunk / =@yassimba/pi-herdr-worktree=.
- Mid-history rewind (Pi =/fork= from an old user message).
- Reusing an existing worktree or branch as the destination.
- Auto-closing the source pane, auto-deleting a failed checkout, merge-back, or cleanup UX.
- Extra flags to split branch name from compact prompt.
- Changing =agent/extensions/herdr-agent-state.ts= (Herdr-managed; reinstall overwrites it).

** Exact flow

1. *Validate.* Env, herdr socket, source idle, readable session file, leaf = last persisted leaf, git root, realpath common-dir is not =~/.pi=, porcelain empty (list files if not). Fail before any create.
2. *Name.* Derive a branch slug from focus text if present, else a timestamp/short-hash. Sanitize hard: legal git branch, length cap, no leading =-=, no =..=, no trailing =.lock= (e.g. =feat/herdr-fork-<slug>=). Reject focus text containing newlines or extra leading =/=. Capture: repo root, *commit OID* (not live HEAD), source session path and id, leaf id, current Herdr workspace/pane ids.
3. *Create checkout + workspace.* Do *not* pre-check branch uniqueness (TOCTOU). Let create fail on collision.
   : herdr worktree create --cwd <repo-root> --branch <branch> --base <captured-oid> --label <short> --no-focus
   Never =--focus=.
4. *Parse JSON. Do not predict ids.* Treat exit status, stdout envelope, and stderr separately. Schema-validate: workspace id, checkout path, root pane id. Confirm how JSON is requested (create --help has no =--json=; success may already print JSON). If the shape is wrong, stop and print raw stdout/stderr — but only after extracting any ids that *are* present, so recovery is possible. Validate the root pane's cwd equals the checkout path (=agent start= has no cwd flag).
5. *Poll until that pane is an interactive shell.* Create returning does not mean the shell is ready. Retry; do not treat this race as a permanent fail on the first attempt.
6. *Start Pi in that pane, forking the source session into the new project.* Confirmed: argv after =--= reach the executable, so this *is* =pi --fork <path>=.
   : herdr agent start <unique-name> --kind pi --pane <root-pane-id> -- --fork <source-session-path>
   Argv arrays, no shell interpolation. Unique agent name.
7. *Wait with timeout for idle or blocked* (=herdr agent wait … --until idle --until blocked= plus a timeout). =--until idle= alone never returns on =blocked=.
   - New checkout is an *untrusted* Pi project. "Ready" / start-ok may mean the *trust prompt*, not idle. Do not send compact onto it.
   - Spike: stop and tell the operator to accept trust in the new pane, *or* pass a confirmed trust-skip flag if one exists — pick during impl, do not guess =--approve=.
   - If start times out or =agent_not_ready=: =herdr agent get/read= before printing a rerun. Pi may already occupy the pane; an unconditional =agent start= would be wrong.
8. *Optional compact, clone only — gated.* If focus text was passed:
   - *Until a scratch-pane test is logged on this TODO proving =herdr agent prompt= runs =/compact= as a command:* print the =/compact …= line and do *not* send it.
   - After that test: =herdr agent prompt <name> "/compact <focus text>" --wait --timeout=. Idle is not proof. Confirm a new compaction entry in the *clone* JSONL before claiming success. If no entry, report compact as manual.
   - Never compact the source session.
9. *Report. Leave the source pane running.* Print: branch, checkout path, workspace id, pane id, new agent name, new session id/path (the managed herdr integration already reports session path — query that before inventing discovery), whether compact ran or was left manual, and the isolation caveat (shared =.git=).

** Semantics to keep straight

- Herdr does *not* discover git worktrees created with =git worktree add=. Only =herdr worktree create= / =open= make a grouped workspace.
- =worktree create= = workspace + shell. It does not start Pi and does not copy a session.
- =pi --fork <path|id>= copies the source JSONL into a *new* session file in the *current* project's session dir (cwd of the launched Pi). Active-path after =/tree= is *not* preserved (see preconditions).
- Compaction is lossy for the model; the clone's JSONL still has history.
- Source pane: no =ctx.fork()=, no =ctx.newSession()=, no compact, no close.
- Clone and source share =.git= (refs, stash, hooks, config). Isolation is worktree-local only. A clone-side =git stash=, =git branch -D=, rebase, or =git config= can hit the source. Say so in the report.

** Failure safety

- Source pane is sacred. No close, no compact, no session switch, no cwd change, on any path including errors after create.
- If create succeeds and agent start fails: *keep* the worktree/workspace. Print recovery (=herdr agent start …=) only if =agent get/read= shows the pane is still a shell. Always print remove (=herdr worktree remove --workspace <id>=). Do not auto-remove.
- If start succeeds and compact is gated/fails: keep the clone running with full context; report compact as manual.
- Quote-safe argv; do not interpolate focus text into a shell string; do not type focus text containing newlines into a pane.
- Do not =git reset=, =stash=, or dirty the source tree to make the clean-tree check pass.

** Test matrix (disposable *host* git repo, not =~/.pi=)

Happy path:

- Clean repo, Herdr pane, persisted session that contains a unique marker string.
- =/herdr-fork= with no focus: new grouped workspace, Pi idle *or* stopped at trust with that reported, marker still in context, cwd is the worktree, branch is the new one, source session id/cwd/branch unchanged, no source compaction entry, no rewind, no pane close.
- =/herdr-fork focus on MARKER=: until the compact gate is lifted, clone has full context and the printed =/compact= line; after the gate, clone JSONL has a compaction entry and still knows MARKER; source JSONL has no new compaction entry.

Isolation:

- Edits in the worktree do not appear in the source *worktree*. Source branch unchanged. Shared =.git= caveat is in the report.

Failures (no checkout, or leftover checkout retained with recovery text — never source mutation):

- Dirty source tree (error lists the paths).
- Not a git repo.
- Not in Herdr.
- Target is =~/.pi= (including an aliased path).
- Branch name collision (create fails; no pre-check).
- =herdr= socket down.
- Source not idle / no session file / leaf ≠ last persisted leaf.
- Focus text with newlines.

Contract tests (canned, no live Herdr required): create/start JSON shapes, malformed/error envelopes, argv with spaces and =--=, delayed shell readiness, start-timeout when Pi already owns the pane.

** Success criteria

- One command from a Herdr-hosted Pi session produces a visible grouped worktree workspace with a usable inherited conversation.
- Source invariant: same session id, same cwd, same branch; no compaction entry; no rewind; no pane close. *Not* bit-wise JSONL equality.
- Failures are non-destructive to the source and do not silently delete a successful checkout.
- Spike log records: exact commands, raw create JSON, ids, whether =--fork= landed in the worktree session dir, trust-prompt behavior, and whether compact was printed or proven.

Do *not* edit =herdr-agent-state.ts=. Do *not* install =npm:@yassimba/pi-herdr-worktree= (worktrunk + split-pane, no new workspace row).
